# MVP.md — «Автодиспетчер» за 1 час

Цель: за час получить **работающее ядро бэкенда** и простой экран, чтобы показать команде весь путь: поезда едут → случился сбой → настоящий CP-SAT за секунды выдаёт 3 варианта с цифрами → применяем → what-if «60 вместо 80» → профиль скорости.

Это фаза 0 из `CLAUDE.md`. Структура пакетов, модели и имена — **те же**, что в `CLAUDE.md`, чтобы MVP вырос в полную версию без переписывания. Где MVP упрощает — сказано явно.

---

## 1. Что входит и что упрощено

| Блок | В MVP | Упрощение относительно CLAUDE.md |
|---|---|---|
| Данные | `infra.json`, `rolling_stock.json`, `timetable.json` из CLAUDE.md §9 (6 пунктов, 10 поездов) | `timetable.json` можно написать руками с примерными временами |
| Модели | `railcore/models.py` целиком по §8 | — |
| Время хода | `running_time.py` | Без физики: `t_pp = length / (0.9 · v)`, где `v = min(v_max поезда, v_max перегона, override)`; надбавки `sup_start = sup_end = 60 с`. Подъём для грузового: `v` на `STP-R2` × 0.6 |
| Шина | `MemoryBus` | Без RabbitMQ |
| Поле | `field/sim.py` | Поезда **исполняют план**: позиция = линейная интерполяция внутри интервала `run`; без ДЦ и сигналов. Если следующий перегон закрыт сбоем — поезд стоит на пункте, `delay_s` растёт |
| Сбои | `obstacle`, `train_failure`, `segment_closed` | Остальные типы — фаза 3 |
| Планировщик | **Настоящий CP-SAT** §12.2 | Вместо назначения конкретных путей — `AddCumulative` по числу путей пункта (без проверки длины). Без refresh и CDR |
| Варианты | 3 стратегии параллельно (`balanced`, `robust`, `passenger_first`/`rescue`) | Оценка устойчивости — повторное решение не нужно, просто пересчёт задержки при `max` через `evaluate` из §12.5 (если не успеваешь — пропусти, оставь `None`) |
| Индекс | §14 | Факторы `schedule`, `conflicts`, `accuracy` полноценно; `capacity` и `energy` — по упрощённым формулам (энергия = число остановок) |
| What-if | `train_speed`, `incident_duration` | Остальные модификации — фаза 6 |
| Автоведение | Эко-профиль одного перегона | Без Дэвиса: разгон `a = 0.4` (пасс.) / `0.15` (груз.), торможение `b_service`, выбег `−0.03 м/с²`; алгоритм из §13 тот же |
| API | REST + WS | Без авторизации, без БД, без истории |
| Фронт | Один `web-mvp/index.html` с ECharts из CDN, отдаётся FastAPI | Без сборки, без React |

## 3. API MVP (без авторизации)

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/infra` | Топология и категории |
| GET | `/api/plan` | Текущий план |
| POST | `/api/incidents` | `{type, segment_id?, train_id?, km?, est_min_min, est_max_min}` → `Incident`; запускает генерацию вариантов |
| POST | `/api/incidents/{id}/resolve` | Снять сбой |
| GET | `/api/variants` | Активные варианты |
| POST | `/api/plan/apply` | `{variant_id, base_plan_version}`; 409 если устарел |
| POST | `/api/whatif` | `{modifications: [...]}` → `WhatIfResult` (синхронно, ≤ 3 с) |
| GET | `/api/ato/{train_id}` | Профиль скорости на ближайший перегон |
| POST | `/api/sim/clock` | `{paused, speed}` |
| WS | `/ws` | При подключении snapshot; дальше `field.state` (2 Гц), `kpi.index` (1 Гц), `planner.variants`, `plan.approved`, `incident.*` |

Swagger `/docs` работает из коробки — показать команде.

## 4. Экран `web-mvp/index.html`

Один файл, ECharts с `cdnjs`, ванильный JS, тёмная тема.

- **Верх:** часы симуляции, кнопки ⏸ ×10 ×20 ×60, индекс крупно с цветом категории, «план пересчитан за N мс».
- **Схема участка (SVG):** линия, 6 пунктов с названиями, поезда — цветные кружки с номерами, закрытые перегоны красным.
- **Поездограмма (ECharts):** X — время (−20 … +120 мин), Y — км с подписями пунктов; факт сплошной, план пунктиром; сбой — красный прямоугольник; вертикаль «сейчас»; при наведении на карточку варианта — его план полупрозрачными линиями поверх.
- **Правая панель:**
  - кнопки сбоев: «Скот на перегоне Рзд. 1 — Степная (15–30 мин)», «Поломка 2003 (20–45 мин)», «Закрытие Рзд. 2 — Озёрная (30 мин)»;
  - 3 карточки вариантов: название, Δиндекс, суммарная задержка, топ-3 опоздавших, объяснение, время решения, «Применить»;
  - what-if: выбор поезда, слайдер скорости, слайдер длительности сбоя, «Рассчитать» → Δиндекс, изменения прибытия, «призрак» на графике;
  - автоведение: выбор поезда → график скорость/путь, раскрашенный по режимам, экономия %.

## 5. План работ на 60 минут

| Минуты | Что | Готово, когда |
|---|---|---|
| 0–10 | Данные §9, `models.py`, `infra.py`, упрощённый `running_time.py`, `config.py` | `python -c` загружает участок и печатает времена хода |
| 10–30 | `planner/model.py` (CP-SAT §12.2 с упрощениями), `strategies.py`, `variants.py` с `ProcessPoolExecutor`, `evaluate.py`, `index.py`, `meetings.py`, `explain.py` | Тест: план v1 без пересечений на перегонах; сбой → 3 варианта ≤ 5 с |
| 30–40 | `bus/memory.py`, `field/sim.py`, `field/incidents.py`, `planner/main.py`, `whatif.py`, `eco.py`, `app/all.py` | В логах поезда двигаются, сбой порождает варианты |
| 40–55 | `api/*`, `web-mvp/index.html` | Всё видно в браузере |
| 55–60 | `tests/test_mvp_smoke.py`, прогон демо | Демо §6 проходит |

Если не укладываешься — режь в таком порядке: автоведение → what-if по длительности сбоя → устойчивость. CP-SAT, варианты и поездограмму **не режь** — это суть показа.

## 6. Демо для команды (DoD)

1. `python -m app.all`, открыть http://localhost:8000. Поезда едут, поездограмма рисует факт и план, индекс в «Норме».
2. Открыть `/docs` — показать, что API полный и описан.
3. «Скот на перегоне» → на графике красный блок, через ≤ 5 с — 3 карточки с цифрами и объяснением.
4. Навести на карточки — видно, как меняются скрещения. Применить → план перестроен, поезда едут по новому.
5. What-if: 2003 → 60 км/ч → «призрак» и Δиндекс, текущий план не изменился.
6. Автоведение для 2004 → профиль с накатом и экономией.
7. `pytest tests/test_mvp_smoke.py` — зелёный: на перегонах никогда два поезда, варианты ≤ 5 с.

## 7. Как MVP перерастает в полную версию

- `running_time.py` → физика §10 (интерфейс тот же: `t_pp`, `sup_start`, `sup_end`, энергия).
- `field/sim.py` → driver + interlocking + safety §11; поезда начинают ехать по физике и сигналам, а не по интерполяции плана.
- `AddCumulative` → назначение путей через опциональные интервалы §12.2.
- `MemoryBus` → `RabbitBus`; `app/all.py` → отдельные контейнеры.
- `web-mvp/` → `web/` на React; контракт WS тот же.
- Добавляются auth, recorder, TimescaleDB, история, отчёты, CDR, refresh.
