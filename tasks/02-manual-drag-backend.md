# tasks/02-manual-drag-backend.md — указания диспетчера через ГИД (бэкенд)

## Суть

Диспетчер на ГИД перетаскивает время **прибытия** или **отправления** поезда на раздельном пункте. Бэкенд:
1. отдаёт допустимые границы перетаскивания;
2. во время перетаскивания быстро считает, как изменение расходится на другие поезда (превью);
3. после отпускания предлагает 2 варианта: «Сохранить порядок» и «Переразвести»;
4. после применения запоминает изменение как **указание диспетчера** (закрепление), которое учитывают все последующие пересчёты.

Фронт ничего не досчитывает сам: только ограничивает мышь по границам и рисует то, что вернул бэк. Отдельное ТЗ для фронта — `tasks/02-manual-drag-frontend.md`, контракт API в обоих файлах одинаковый.

Перед началом прочитай в `CLAUDE.md` разделы 8, 12.2, 12.5, 12.8, 13, 15, 16, 25, 27 и текущий код планировщика (`planner/model.py`, `railcore/evaluate.py`, what-if, варианты).

## 1. Правила для перетаскиваемого поезда

Обозначения: пункт `i`, предыдущий пункт `i−1`, `now` — текущее время симуляции, `t_min(i−1→i)` — минимальное время хода по тяговому расчёту с учётом остановок на концах (`t_pp + sup_start·stop + sup_end·stop`).

### 1.1 Отправление с пункта `i` → время `t`

| Направление | Поведение |
|---|---|
| Влево | Стоянка уменьшается. Нижняя граница — максимум из: `now`; `arr_i + min_dwell` (плановая остановка) или `arr_i + t_pass` (проход); `sched_dep_i` для пассажирских и скорых на плановой остановке; `sched_dep` на станции отправления для пассажирских и скорых |
| Вправо | Стоянка растёт. Время хода на следующих перегонах **не меняется** (скорость та же), вся нитка поезда после `i` сдвигается вправо на Δ. Верхняя граница — `now + horizon_s` |

### 1.2 Прибытие на пункт `i` → время `t`

Отправление с `i−1` не меняется, время хода перегона `i−1→i` становится `t − dep_{i−1}`.

| Направление | Поведение |
|---|---|
| Влево | Ход быстрее, стоянка на `i` растёт, отправление с `i` остаётся. Нижняя граница — `dep_{i−1} + t_min(i−1→i)`; если поезд уже на этом перегоне — `now + остаток минимального хода` от текущих `pos_m`, `speed` |
| Вправо | Ход медленнее. Отправление с `i` остаётся, пока `dep_i − t ≥ min_dwell` (или `t_pass`); дальше `dep_i = t + min_dwell` и нитка после `i` сдвигается вправо. Верхняя граница — `dep_{i−1} + t_min · max_run_factor` (по умолчанию `2.0`): дальше поезд фактически стоял бы на перегоне, это делается задержкой отправления с `i−1` |

### 1.3 Особые точки

| Точка | Что можно |
|---|---|
| Станция отправления поезда | Только отправление |
| Конечная станция | Только прибытие |
| Проход без остановки (`arr = dep`) | Обе ручки на одной точке. Вправо = отправление (появляется стоянка, `stop = true`, `unplanned = true`); влево = прибытие (ускорение на предыдущем перегоне, появляется стоянка) |
| Событие уже в прошлом (`≤ now`) | Заблокировано: `locked = true`, причина «Поезд уже отправился» / «Поезд уже прибыл» |
| Поезд в режиме перемотки / `FINISHED` / отменён | Заблокировано |

Шаг времени — 60 с. Бэкенд округляет `time` до минуты.

## 2. Модель «указание диспетчера» (закрепление)

Добавить в `railcore/models.py`:

```python
class Pin(BaseModel):
    id: str
    train_id: str; station_id: str; kind: Literal["arr", "dep"]
    time: float                                  # sim seconds
    created_at: float                            # sim seconds
    status: Literal["active", "violated", "done", "removed"]
    reason: str | None = None                    # for violated
    description: str                             # «Задержать 2003 отправлением со Степной до 10:42»
```

- `Plan` получает поле `pins: list[Pin]` (активные и нарушенные).
- `Variant` получает `source: Literal["incident", "manual", "return_to_schedule", "whatif"]` и `manual: dict | None` (`{train_id, station_id, kind, from_time, to_time}`).
- Указание становится `active` только при применении варианта. Пока диспетчер не применил — это просто превью.
- `done` — событие наступило (`time ≤ now` и поезд его выполнил). Такие указания из плана убираются.
- Указание не снимается автоматически ни refresh, ни новым сбоем — только диспетчером.

Запись в раздел 25 `CLAUDE.md`: «Указания диспетчера (Pin) — жёсткие ограничения для всех пересчётов».

## 3. Расчёты

### 3.1 Границы (`planner/manual.py: bounds`)

По правилам раздела 1 для обеих ручек точки. Каждая граница возвращается с кодом причины:

| Код | Текст для UI |
|---|---|
| `now` | Нельзя раньше текущего времени |
| `schedule` | Не раньше отправления по расписанию |
| `min_dwell` | Минимальная стоянка N мин |
| `min_run_time` | Быстрее нельзя: минимальное время хода N мин (средняя X км/ч) |
| `max_run_time` | Медленнее нельзя: задержите отправление с предыдущего пункта |
| `horizon` | Дальше горизонта планирования |
| `pin` | Ограничено указанием диспетчера по этому поезду |

Если на этом поезде уже есть активное указание на **другой** точке, оно учитывается как фиксированное. Указание на **этой же** точке игнорируется (его и двигаем).

### 3.2 Превью — «протяжка задержки» (`evaluate` в режиме фиксированных длительностей)

Расширить `railcore/evaluate.py`:
- новый режим `durations="planned"`: длительности хода берутся **из текущего плана**, а не минимальные (скорость поездов не меняется);
- нижние границы событий:
  - для всех поездов, кроме перетаскиваемого, — их текущие плановые времена (превью никого не сдвигает раньше);
  - для перетаскиваемого после точки — только расписание, мин. стоянки и указания;
- новое время точки — фиксированное (нижняя и верхняя граница = `time`);
- для `arr`: длительность перегона `i−1→i` = `time − dep_{i−1}`;
- порядок поездов на перегонах и путях — из текущего плана; интервалы — как в 12.5 (межпоездной, τск, τнп).

Результат превью:
- нитки **только затронутых** поездов (изменилось хотя бы одно время) — точки по пунктам;
- по каждому затронутому: изменение прибытия на конечную в горизонте и максимальное изменение по пути;
- конфликты (если фиксированный порядок даёт нарушение, например закреплённое время упирается в окно);
- прогноз индекса и Δ к текущему;
- для перетаскиваемого: новая стоянка, время хода и средняя скорость на перегоне `i−1→i`, максимальная скорость перегона.

Цель: ≤ 100 мс на сервере. CP-SAT в превью **не вызывать**.

### 3.3 Фиксация — 2 варианта

После отпускания мыши, параллельно:

1. **«Сохранить порядок»** (`strategy="keep_order"`) — то же, что превью: протяжка задержки при текущих скрещениях и обгонах.
2. **«Переразвести»** (`strategy="reoptimize"`) — CP-SAT по 12.2 со всеми активными указаниями плюс новым, стратегия весов `balanced`, warm start от текущего плана. Может поменять скрещения, чтобы другие поезда потеряли меньше.

Если «Переразвести» дало тот же порядок или выигрыш < 60 с взвешенной задержки — вернуть только «Сохранить порядок» и в объяснении написать «Перестановка скрещений не даёт выигрыша».

Оба — обычные `Variant` (`source="manual"`) с KPI, индексом, Δ, объяснением; публикуются в `planner.variants` и возвращаются в ответе. Применение — существующим `POST /api/plan/apply`. При применении указание становится `active` и попадает в `plan.pins`.

Цель: ≤ 5 с на оба варианта.

### 3.4 Указания в CP-SAT (`planner/model.py`)

- `kind="dep"`: `dep[j,i] == time`.
- `kind="arr"`: `arr[j,i] == time`; для перегона `i−1→i` этого поезда верхняя граница длительности расширяется до `t_min · max_run_factor` (обычные 1.3 не действуют).
- Если модель с указаниями `INFEASIBLE` (например, новый сбой сделал указание невозможным):
  1. решить повторно с мягкими указаниями: штраф `M · |отклонение|`, `M = 10 000` за секунду;
  2. указания с отклонением > 0 → `status="violated"`, `reason` текстом;
  3. опубликовать `planner.pin_violated {pin, reason}`;
  4. диспетчер решает: снять указание или принять отклонение.
- Указания учитываются **везде**: refresh, варианты при сбоях, what-if, «Возврат к графику», fallback (`evaluate` берёт их как фиксированные времена).

### 3.5 Снятие указания

`DELETE /api/plan/pins/{id}` → `status="removed"`. Снятие ограничения не создаёт конфликтов, поэтому план не меняется сразу. Дальше по правилу из `CLAUDE.md` §12.1: CP-SAT считает план без указания, и если выигрыш ≥ 5 мин взвешенной задержки — предлагается вариант «Возврат к графику» (`source="return_to_schedule"`), иначе ничего.

### 3.6 Поле и автоведение

- ДЦ: маршрут отправления по указанию `dep` задаётся не раньше чем за 60 с до `time` (поезд держится на пункте).
- Автоведение: при указании `arr` целевое время хода перегона = `time − dep_{i−1}` — профиль сам уйдёт в накат, экономия энергии видна в панели автоведения.
- Журнал ДЦ: «Указание диспетчера: задержать 2003 отправлением со Степной до 10:42 (+7 мин)», «Указание снято», «Указание нарушено: …».

### 4.4 Указания

- `GET /api/plan/pins` → `[Pin]`.
- `DELETE /api/plan/pins/{id}` → `{ok: true}`; дальше по 3.5.
- Применение варианта — существующий `POST /api/plan/apply {variant_id, base_plan_version}`.

### 4.5 Ошибки

| Код | Когда | Тело |
|---|---|---|
| 409 `stale_plan` | `base_plan_version` ≠ текущей | `{"error": "stale_plan", "current_version": 18}` |
| 423 `locked` | Точка заблокирована (прошлое, поезд прибыл, перемотка) | `{"error": "locked", "reason": "Поезд уже отправился"}` |
| 404 `not_found` | Нет такого поезда или точки в плане | `{"error": "not_found"}` |
| 422 `invalid_kind` | `arr` для станции отправления / `dep` для конечной | `{"error": "invalid_kind"}` |

### 4.6 WebSocket

- `plan.approved` / `plan.refreshed` — `Plan` теперь содержит `pins`.
- `planner.variants` — варианты с `source="manual"`.
- `planner.pin_violated` — `{pin: Pin, reason: str}`.

## 6. Тесты

- **bounds**: отправление пассажирского не раньше расписания; отправление не раньше `arr + min_dwell`; прибытие не раньше `dep_{i−1} + t_min`; прибытие поезда, уже находящегося на перегоне, — от остатка хода; прошлые точки `locked`; станция отправления без `arr`, конечная без `dep`.
- **preview dep вправо**: все последующие времена этого поезда +Δ, длительности хода не меняются.
- **preview arr влево**: стоянка растёт, отправление не меняется, время хода перегона = `time − dep_{i−1}`.
- **preview arr вправо**: пока стоянка ≥ минимальной — отправление на месте; после — сдвиг на остаток.
- **preview pass**: проход превращается в стоянку с `unplanned = true`.
- **preview остальных поездов**: никто не сдвигается раньше своего плана; встречный за скрещением получает задержку.
- **commit**: 2 варианта; при отсутствии выигрыша — 1; `apply` делает указание `active`.
- **указания в CP-SAT**: refresh и варианты при сбое сохраняют время указания; при невыполнимом указании — `violated` и событие.
- **снятие**: план не меняется сразу; при выигрыше ≥ 5 мин появляется «Возврат к графику».
- **stale**: preview/commit со старой версией → 409.
- **производительность**: bounds ≤ 50 мс, preview ≤ 100 мс, commit ≤ 5 с на непрерывном расписании.
- **stress**: `tools/stress.py` и `tools/e2e_dispatcher.py` с серией случайных указаний — 0 нарушений безопасности, 0 зависаний.
